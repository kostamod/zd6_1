WORLDCINEMA — ДОПОЛНЕНИЕ ДЛЯ ЗАЩИТЫ

В этой версии каталог и избранное используют Wear Compose. Остальные экраны остались на XML и Android Views. Каталог и постеры локальные. OMDb не подключён по последнему указанию. Ниже — конспект презентации и описание обновлённого списка.

КОНСПЕКТ ПРЕЗЕНТАЦИИ

1. Wear OS — платформа Android для часов. Маленький круглый экран удобнее для коротких действий: быстро взглянуть, прокрутить список, выбрать элемент. На телефоне больше места для текста, вкладок и длинных сценариев. На часах важно уменьшать число одновременных действий, учитывать обрезку по краям и экономить заряд.
2. Новый проект на слайдах создаётся из шаблона Empty Wear OS App на Kotlin с minSdk 26 или выше. В WorldCinema сохранён существующий minSdk 28. В манифесте указан обязательный тип watch и метаданные самостоятельного приложения.
3. Compose описывает интерфейс через функции. При изменении наблюдаемого состояния Compose обновляет затронутую часть интерфейса. remember хранит значение между рекомпозициями, mutableStateOf делает изменения наблюдаемыми. rememberSaveable добавляет восстановление поддерживаемого значения из сохранённого состояния. В каталоге состояние позиции создаётся через rememberScalingLazyListState.
4. BoxInsetLayout — контейнер системы Android Views для отступов на круглом дисплее. CurvedText размещает текст вдоль дуги. ScalingLazyColumn — список Wear Compose, который уменьшает элементы по мере приближения к краям. PositionIndicator показывает положение прокрутки. В работе используются два последних компонента.
5. Ambient — режим низкого энергопотребления для отображения минимальной информации при отсутствии активного взаимодействия. Для него ограничивают частоту обновлений, яркие области и анимации. В работе отдельный Ambient-интерфейс не реализован.
6. SensorManager даёт доступ к датчикам. TYPE_STEP_COUNTER возвращает накопительное число шагов с последней перезагрузки устройства, пока датчик активен. Для шагов за сеанс сохраняют начальное значение и вычитают его из текущего. На Android 10+ для доступа к счётчику шагов нужно объявить и запросить ACTIVITY_RECOGNITION. Проверяют доступность датчика и снимают слушатель, когда он больше не нужен. Это пример с презентации, в каталоге фильмов датчик не используется.
7. Фоновая сеть и вычисления расходуют батарею из-за пробуждений процессора и радиомодулей. Производительность чипа эту стоимость не устраняет. Для проверки без физических часов используют Android Emulator с образом Wear OS. Поддержку конкретного датчика надо проверять отдельно.
8. Последний слайд предлагает отдельный макет трекера привычек. Сдаваемая работа в этом репозитории — WorldCinema по варианту KOD1.4 Variant2.

ЧТО ПОКАЗАТЬ В КОДЕ

app/build.gradle.kts — buildFeatures включает Compose, composeOptions задаёт версию компилятора 1.5.1 под Kotlin 1.9.0, dependencies подключает androidx.wear.compose:compose-material:1.3.1. Эта зависимость предоставляет Wear Material и подключает Wear Compose Foundation, где находится ScalingLazyColumn. Picasso 2.8 продолжает обслуживать изображения.
MoviesFragment.kt — создаёт ComposeView внутри существующего Fragment. ViewCompositionStrategy освобождает композицию при уничтожении View фрагмента. В Scaffold находятся ScalingLazyColumn и PositionIndicator. Оба получают один listState, поэтому индикатор следует за списком.
AndroidView в MoviesFragment.kt встраивает старую карточку из MovieViews.kt в Compose. Карточка по-прежнему содержит ImageView, поэтому Picasso.get().load(...).placeholder(...).into(...) работает через тот же загрузчик.
ScalingLazyColumn создаёт элементы по мере необходимости в области списка. Положение карточки влияет на её масштаб. Свайп перемещает список, PositionIndicator показывает его положение. Горизонтальные отступы уменьшают риск обрезки на круглом экране.
Остальные фрагменты используют общий XML ScrollView. В Ui.kt scroller() создаёт контейнер сообщений, а прокрутку всей страницы предоставляет ScrollView из XML.

ВОПРОСЫ ПРЕПОДАВАТЕЛЯ

— Где подключена Wear-библиотека и что она делает?
В зависимости compose-material в app/build.gradle.kts. В MoviesFragment видны её PositionIndicator и Scaffold, а ScalingLazyColumn приходит из Wear Compose Foundation.

— Как сохранились старые карточки после перехода на Compose?
Compose управляет списком. AndroidView создаёт прежнюю карточку с ImageView, обработчиком нажатия и Picasso.

— Чем отличается скролл каталога от скролла чата?
Каталог прокручивает масштабируемый ленивый список и показывает индикатор. Чат прокручивает обычный вертикальный XML-контейнер целиком.

— Откуда берутся данные?
Из встроенного каталога Movie.kt. Постеры находятся в assets/posters и загружаются Picasso. Запросы к OMDb в этой версии не выполняются.

— Как показать библиотеку на защите?
Открыть каталог на часах, прокрутить четыре карточки, показать изменение масштаба и индикатор. После этого открыть MoviesFragment.kt и dependency в app/build.gradle.kts.

Источники: презентация преподавателя «Создание приложения для умных часов в Android Studio на Kotlin», документация Picasso https://square.github.io/picasso/.

3. ПОТОК РАБОТЫ ПО ФАЙЛАМ

AndroidManifest.xml
- uses-feature android.hardware.type.watch с required=true объявляет обязательную категорию устройства. Это важно для фильтрации устройств при распространении приложения.
- com.google.android.wearable.standalone=true объявляет приложение самостоятельным на часах.
- MAIN и LAUNCHER делают MainActivity точкой входа из списка приложений.
- exported=true позволяет системе запустить MainActivity извне.
- screenOrientation=portrait задаёт портретную ориентацию, allowBackup=false отключает участие приложения в резервном копировании через этот флаг.

MainActivity.kt
- Наследуется от AppCompatActivity. onCreate() загружает activity_main.xml с FrameLayout и ID content.
- При savedInstanceState == null открывает LoginFragment. При восстановлении FragmentManager сам восстанавливает фрагменты, и без условия стартовая форма могла бы заменить восстановленный экран.
- show(fragment, back = true) заменяет текущий фрагмент в content. При back=true транзакция помещается в back stack. При back=false накопленная история очищается, новая транзакция в историю не добавляется.
- favorites: MutableSet<String> — набор ID сериалов. messages: MutableMap<String, MutableList<String>> — сообщения по темам. Это поля экземпляра Activity.

LoginFragment.kt
- Использует fragment_login.xml. В XML есть EditText с типами textEmailAddress и textPassword и кнопка login.
- onViewCreated получает кнопку через findViewById и назначает setOnClickListener. «Войти» открывает MenuFragment с back=false.
- Логин и пароль здесь вообще не читаются обработчиком. Пустые поля не блокируют вход. У пароля отключено сохранение значения самим View через saveEnabled=false.

MenuFragment.kt
- Использует fragment_page.xml. К полученному LinearLayout добавляет GridLayout с двумя колонками.
- Каждый пункт содержит ImageView с иконкой и текстовую подпись. Размеры зависят от screenWidthDp.
- «Обсуждения» открывает DiscussionFragment, «Фильмы» — MoviesFragment, «Избранное» — MoviesFragment.favorites().
- «Выйти» возвращает форму входа и очищает историю экранов. Коллекции в Activity при этом не очищаются.

Movie.kt
- data class Movie содержит id, title, year, description. val poster вычисляет путь по ID, например file:///android_asset/posters/witcher.jpg.
- Год хранится строкой, здесь он нужен для отображения.
- Встроенный список movies содержит The Witcher, Lucifer, LOST и The Magicians.

MoviesFragment.kt
- В обычном режиме показывает весь каталог. В режиме избранного читает флаг favorites из arguments и оставляет только записи, у которых ID входит в host.favorites.
- Для каждой записи вызывает movieCard() и передаёт обработчик нажатия. Обработчик вызывает DetailsFragment.create(movie.id).
- При пустом избранном выводится подсказка. Часть навигации реализована явной кнопкой «Меню», которая очищает историю.

MovieViews.kt
- movieCard() строит FrameLayout со слоями: картинка, затемнение, значок ▶, название и год. Карточка целиком реагирует на нажатие и открывает описание.
- loadPoster() использует Picasso.get().load(...).placeholder(...).error(...).fit().centerCrop().into(image).
- placeholder показывает картинку на время загрузки. error показывает её при ошибке. fit подбирает размер под ImageView, centerCrop заполняет область и может обрезать края, сохраняя пропорции.
- При пустом пути или N/A предыдущий запрос для ImageView отменяется, затем ставится заглушка.

DetailsFragment.kt
- create(id) кладёт ID в Bundle под ключом movieId. onViewCreated ищет запись через firstOrNull. Если ID отсутствует или не найден, метод выходит без заполнения страницы.
- Отображает постер, год и описание. Нажатие на сердечко вызывает favorites.add(id). Если add вернул false, ID уже был в наборе и его удаляют. Текст кнопки обновляется сразу.
- «Обсуждение» открывает ChatFragment и передаёт название сериала. «Назад» вызывает popBackStack().

DiscussionFragment.kt и ChatFragment.kt
- DiscussionFragment выводит четыре темы. В этой реализации названия тем прописаны отдельным списком, поэтому при расширении каталога его тоже надо обновить.
- ChatFragment.create(room) передаёт название через Bundle. getOrPut(room.lowercase()) берёт список для темы или создаёт пустой. Нижний регистр позволяет темам с разным регистром использовать один список.
- «Добавить» читает текст, удаляет пробелы с краёв через trim(). Если строка непустая, добавляет её в список, очищает поле и вызывает render().
- render() удаляет старые View из контейнера сообщений и создаёт подписи заново. Для небольшой демонстрации это просто. Для длинной истории лучше использовать RecyclerView и обновлять элементы списка выборочно.
- У сообщений нет автора, даты, отправки по сети и синхронизации. Они доступны локально, пока живёт Activity.

Ui.kt
- Общие функции расширения для LinearLayout: label() создаёт TextView, heading() — заголовок, action() — кнопку с обработчиком, input() — EditText.
- scroller() по факту добавляет обычный вертикальный LinearLayout. Прокрутка обеспечивается внешним ScrollView в XML общей страницы.
- Context.dp() переводит dp в пиксели через плотность экрана, когда размеры задаются из Kotlin.

4. ТЕОРИЯ, КОТОРУЮ МОГУТ СПРОСИТЬ

Activity — системный компонент с окном и жизненным циклом. Fragment — часть интерфейса внутри Activity, у него есть свой жизненный цикл и отдельный жизненный цикл его View. В этом проекте Activity одна, её содержимое меняется заменой Fragment.
onCreate() Activity подходит для настройки окна. onViewCreated() фрагмента вызывается после создания разметки, там можно искать View и привязывать обработчики. При уходе с экрана View фрагмента может быть уничтожено раньше самого фрагмента.
Back stack хранит операции навигации. Bundle передаёт небольшие параметры: здесь String с ID, String с темой и Boolean режима избранного. Bundle с аргументами помогает восстановить входные параметры фрагмента.
View — один элемент интерфейса. ViewGroup — контейнер для других View. FrameLayout накладывает слои, LinearLayout ставит элементы в ряд или колонку, GridLayout раскладывает по сетке, ScrollView даёт вертикальную прокрутку.
dp — единица для размеров и отступов с учётом плотности экрана. sp — единица для текста, учитывает и пользовательский масштаб шрифта. px — физический пиксель. screenWidthDp сравнивает доступную ширину в dp.
R — сгенерированный класс идентификаторов ресурсов. R.layout указывает на разметку, R.id — на элемент, R.drawable — на картинку или оформление. Файлы assets открываются по пути, без отдельных идентификаторов R.
XML описывает каркас интерфейса. Kotlin создаёт динамическое содержимое: карточки, кнопки меню, сообщения. Это Android Views, В каталоге используется Compose с AndroidView, остальные экраны используют XML и Views.
layout-watch — квалификатор для режима устройства «часы». Android выбирает подходящий вариант ресурса при запросе того же R.layout. Проверка ширины < 300 dp отдельно задаёт компактные параметры в коде. Наличие layout-watch само по себе не гарантирует идеальную компоновку на дисплеях любой формы.
Data class подходит для модели данных. Kotlin генерирует equals(), hashCode(), toString(), copy() и componentN() на основе свойств конструктора. val запрещает переназначить ссылку, но содержимое mutableSetOf или mutableMapOf менять можно.
List — упорядоченный список. Set хранит уникальные значения, поэтому подходит для ID избранных. Map хранит пары ключ и значение, поэтому подходит для поиска истории по теме.
Лямбда — функция, которую можно передать как параметр. В movieCard параметр click имеет тип () -> Unit. Код карточки вызывает его, а экран решает, куда перейти.
minSdk=28 — нижняя граница API для установки. compileSdk=34 — версия API, доступная при компиляции. targetSdk=34 — версия, под правила поведения которой заявлено приложение. API 28 соответствует Android 9, API 34 — Android 14. Это номера базовой платформы Android, не номера релизов Wear OS.
namespace — пространство имён для сгенерированного R. applicationId — уникальный ID установленного приложения. Здесь оба com.modestov.worldcinema. versionCode=1 — числовая версия для обновлений, versionName=1.0 — строка для отображения.
Gradle выполняет задачи сборки, AGP добавляет поддержку Android, Kotlin plugin компилирует Kotlin. Проект нацелен на JVM bytecode 1.8, при этом для запуска AGP 8.2 требуется JDK 17. Это разные настройки.
APK — пакет для установки с манифестом, кодом DEX, ресурсами и assets. Android Studio — среда разработки. Android SDK даёт API и инструменты. AndroidX AppCompat 1.6.1 даёт AppCompatActivity, Fragment KTX 1.6.2 — фрагменты и их Kotlin-интеграцию. Picasso 2.8 загружает изображения.

5. ВОПРОСЫ ПРЕПОДАВАТЕЛЯ И КОРОТКИЕ ОТВЕТЫ

— Где в коде доказательство, что работа для часов?
В манифесте указаны тип watch и standalone. В res/layout-watch есть отдельные варианты формы входа и общей страницы. В Ui.kt, MenuFragment.kt и MovieViews.kt размеры зависят от ширины.

— На чём держится переход «каталог → подробности»?
Обработчик нажатия передаёт movie.id в DetailsFragment.create(). ID попадает в arguments через Bundle. DetailsFragment находит объект в movies.

— Почему одна Activity?
Она служит общим контейнером и хранит состояние на время сеанса. Фрагменты разделяют логику экранов, а FragmentManager управляет переходами.

— Что будет, если из карточки добавить сериал в избранное дважды?
Первое нажатие добавит его ID в набор, второе удалит. Дубликаты в Set невозможны.

— Что если добавить сообщение из карточки, а потом открыть обсуждение из меню?
Оба пути передают название того же сериала, поэтому выбирается один и тот же список сообщений.

— Почему обсуждения четырёх сериалов не смешиваются?
Для каждого названия темы в Map отдельный список. Название приводится к нижнему регистру.

— Будут ли избранное и чат после выхода через кнопку «Выйти»?
В рамках текущей Activity да. Кнопка меняет экран, а коллекции остаются. После нового запуска или пересоздания Activity они пустые.

— Поможет ли ViewModel сохранять данные между всеми запусками?
ViewModel подходит для переживания пересоздания Activity при изменении конфигурации. Для долговременного хранения нужны данные на диске: например, DataStore для небольших настроек и Room для сериалов и истории сообщений.

— Можно ли смотреть сериал прямо на часах?
Проект показывает информацию о сериале. ▶ служит элементом карточки, нажатие открывает описание.

— Что происходит без интернета?
Каталог, постеры, избранное и добавление сообщений работают локально. В приложении нет обращения к серверу для этих действий.

— Откуда постеры и зачем Picasso, если файлы локальные?
Источники перечислены в POSTER_CREDITS.txt. Picasso умеет читать assets, масштабировать с обрезкой по центру и показывать заглушку.

— Что произойдёт при ошибке изображения?
Picasso покажет drawable bill_up_close. При пустом адресе код сразу установит этот ресурс.

— Зачем прокрутка, если каталог всего из четырёх записей?
В обновлённом каталоге прокрутку выполняет ScalingLazyColumn. На страницах входа, описания и чата прокрутку выполняет внешний ScrollView.

— Есть ли здесь виджет, циферблат или Tile?
Это полноэкранное приложение, которое открывается через список приложений. В проекте точкой входа служит Activity.

— Чем Lint отличается от проверки на устройстве?
Lint статически анализирует код и ресурсы, например проверяет совместимость API. Запуск на часах показывает поведение интерфейса, навигации, клавиатуры и прокрутки.

— Как собрать работу на Windows?
Из корня проекта: .\gradlew.bat :app:assembleDebug. Обычный путь APK: app/build/outputs/apk/debug/app-debug.apk. Для статической проверки: .\gradlew.bat :app:lintDebug. Для показа можно выбрать часы или Wear OS AVD в Android Studio и запустить конфигурацию app.

— Что бы доработал в первую очередь?
Для сохранения данных добавил бы постоянное хранилище, например Room для избранного и сообщений. Для тем использовал бы стабильный ID сериала и формировал бы список тем из movies. Для настоящей авторизации и общего чата понадобился бы сервер. На разных часах отдельно проверил бы доступность кнопок и полей ввода.

7. ЧАСЫ И ТЕЛЕФОН: ЧТО ОТЛИЧАЕТСЯ, ГДЕ ЗАВИСИМОСТИ И КАК РАБОТАЕТ СКРОЛЛ

— В чём разница между этой работой и приложением для телефона?
Kotlin, Activity, Fragment и обычные Android Views можно использовать на обоих устройствах. В WorldCinema меняются назначение приложения и компоновка. В AndroidManifest.xml заявлен обязательный тип устройства android.hardware.type.watch, а standalone=true означает, что для работы на часах не требуется приложение на телефоне. При распространении объявление watch используется для фильтрации устройств. Обычные XML из res/layout — базовые ресурсы, а не отдельная версия приложения для смартфона.

— Что конкретно меняется на часах?
Android выбирает одноимённые варианты fragment_login.xml и fragment_page.xml из res/layout-watch. Например, у общей страницы отступы 8 dp вместо 16 dp, а кнопка входа имеет высоту 44 dp вместо 56 dp. Отдельно Kotlin проверяет screenWidthDp < 300 и уменьшает элементы на узком экране. Проверка ширины сработает для любого окна такой ширины. layout-watch выбирается по типу интерфейса устройства. Код не проверяет, круглый ли экран.

— Где я подключил библиотеку для часов?
Библиотека Wear Compose подключена в app/build.gradle.kts через androidx.wear.compose:compose-material:1.3.1. Открой app/build.gradle.kts и покажи блок dependencies: там Wear Compose Material 1.3.1, AppCompat 1.6.1, Fragment KTX 1.6.2 и Picasso 2.8. Для часов также используются манифест, ресурсы layout-watch, компактные размеры и прокрутка. Если преподаватель попросит показать именно «подключение часов», сначала открой AndroidManifest.xml и покажи uses-feature и standalone, затем res/layout-watch. Подключение Gradle-библиотеки показывают отдельно в app/build.gradle.kts.

— Где находится скролл и что прокручивается?
Корневой тег <ScrollView> находится в обоих вариантах fragment_page.xml и в обоих вариантах fragment_login.xml. У ScrollView один прямой ребёнок — вертикальный LinearLayout. На общей странице у него ID page. XML-фрагменты добавляют в него подписи и кнопки. В каталоге список карточек создаёт ScalingLazyColumn. ScrollView занимает ширину и высоту окна через match_parent, а LinearLayout растёт по содержимому через wrap_content. Если содержимое выше видимой области, пользователь свайпом перемещает страницу вверх и вниз. fillViewport=true растягивает короткое содержимое как минимум до высоты видимой области.

— Почему нельзя положить все карточки прямо в ScrollView?
ScrollView допускает только одного прямого ребёнка. Поэтому обычный XML ScrollView прокручивает один контейнер целиком. Новый каталог использует ScalingLazyColumn и создаёт карточки по мере необходимости.

— Ui.kt содержит scroller(). Это отдельный скролл для чата?
Нет. scroller() только создаёт внутренний LinearLayout для сообщений. Заголовок, список сообщений, поле ввода и кнопка «Добавить» находятся на одной странице и прокручиваются вместе благодаря внешнему ScrollView. При добавлении сообщения render() заново заполняет только контейнер сообщений. Автопрокрутка к последнему сообщению отдельно не реализована.

— Почему использован ScrollView, а когда нужен RecyclerView?
Для четырёх карточек это простой способ прокрутить всю страницу. ScrollView держит все добавленные карточки в памяти. Для большого каталога или длинной истории чата RecyclerView позволяет переиспользовать элементы списка при прокрутке. RecyclerView не используется. В обновлённом каталоге его роль выполняет ScalingLazyColumn.

Что показать преподавателю: AndroidManifest.xml → app/build.gradle.kts → res/layout-watch/fragment_page.xml → MoviesFragment.kt (добавление карточек в page) → ChatFragment.kt и Ui.kt (контейнер сообщений). На часах открыть «Фильмы» и показать ScalingLazyColumn и PositionIndicator. XML ScrollView можно показать отдельно на экране обсуждения.
